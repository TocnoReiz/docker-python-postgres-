# Конспект по Docker для новичка

## 1. Что такое Docker

**Docker** — инструмент, который упаковывает программу вместе со всем, что ей нужно для работы (библиотеки, настройки, окружение), в изолированный **контейнер**. Контейнер одинаково запускается на любом компьютере: «у меня работает» превращается в «работает везде».

**Контейнер vs виртуальная машина**

| | Контейнер | Виртуальная машина |
|---|---|---|
| Что внутри | Программа и её зависимости | Целая ОС |
| Размер | Десятки-сотни МБ | Гигабайты |
| Запуск | Секунды | Минуты |
| Ядро ОС | Общее с хостом | Своё |

## 2. Ключевые понятия

- **Образ (image)** — шаблон, «слепок» с программой и окружением. Только для чтения.
- **Контейнер (container)** — запущенный экземпляр образа. Из одного образа можно запустить много контейнеров.
- **Dockerfile** — текстовый файл-рецепт, по которому собирается образ.
- **Docker Hub** — онлайн-хранилище готовых образов (nginx, postgres, python и т.д.).
- **Том (volume)** — хранилище данных вне контейнера, чтобы данные не пропадали при удалении контейнера.
- **Сеть (network)** — виртуальная сеть, через которую контейнеры общаются друг с другом.
- **docker compose** — запуск нескольких контейнеров одной командой по файлу `compose.yaml`.

Аналогия: **образ — класс, контейнер — объект** этого класса.

## 3. Установка и проверка

На Windows ставится **Docker Desktop**. После установки проверь в терминале:

```powershell
docker --version
docker run hello-world
```

Если `hello-world` напечатал приветствие, всё работает. Docker Desktop должен быть запущен, иначе команды будут падать с ошибкой подключения.

## 4. Основные команды

### Образы

```bash
docker pull nginx            # скачать образ
docker images                # список образов
docker rmi nginx             # удалить образ
docker build -t myimage .    # собрать образ из Dockerfile в текущей папке
```

### Контейнеры

```bash
docker run nginx                       # создать и запустить контейнер
docker run -d nginx                    # -d: в фоне
docker run -d -p 8080:80 nginx         # -p: порт_компьютера:порт_контейнера
docker run -d --name web nginx         # задать имя
docker run -it ubuntu bash             # -it: интерактивно, зайти внутрь
docker run --rm myimage                # --rm: удалить контейнер после остановки

docker ps                              # запущенные контейнеры
docker ps -a                           # все, включая остановленные
docker stop web                        # остановить
docker start web                       # запустить снова
docker rm web                          # удалить (остановленный)
docker rm -f web                       # удалить принудительно

docker logs web                        # логи
docker logs -f web                     # следить за логами
docker exec -it web bash               # зайти в работающий контейнер
```

После `docker run -d -p 8080:80 nginx` открой в браузере `http://localhost:8080` — увидишь страницу nginx.

### Уборка

```bash
docker system prune          # удалить остановленные контейнеры и неиспользуемые ресурсы
```

## 5. Dockerfile

Файл называется строго `Dockerfile`, **без расширения** (в Windows проверь, что Блокнот не сохранил его как `Dockerfile.txt`).

### Основные инструкции

| Инструкция | Что делает |
|---|---|
| `FROM` | Базовый образ. С неё начинается любой Dockerfile |
| `WORKDIR` | Рабочая папка внутри образа |
| `COPY` | Копирует файлы с компьютера в образ |
| `RUN` | Выполняет команду **при сборке** образа |
| `ENV` | Задаёт переменную окружения |
| `EXPOSE` | Документирует порт, который слушает приложение |
| `CMD` | Команда по умолчанию **при запуске** контейнера |
| `ENTRYPOINT` | Основная исполняемая команда контейнера |
| `LABEL` | Метаданные образа (автор, версия) |
| `ARG` | Переменная, доступная только при сборке |

> `MAINTAINER` — устаревшая инструкция. Вместо неё: `LABEL maintainer="Имя <почта>"`.

### Пример: Python-приложение

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "main.py"]
```

Сборка и запуск:

```bash
docker build -t myapp .
docker run --rm myapp
```

### RUN vs CMD

- `RUN` выполняется **один раз при сборке** и результат сохраняется в образ (установка пакетов).
- `CMD` выполняется **при каждом запуске** контейнера.

### Форма записи CMD

```dockerfile
CMD ["nginx", "-g", "daemon off;"]   # JSON-форма (exec) — рекомендуется
CMD nginx -g "daemon off;"           # shell-форма — вызывает предупреждение
```

В JSON-форме программа становится главным процессом и корректно получает сигналы (например, от `docker stop`). Только двойные кавычки.

### Кэш слоёв

Каждая инструкция создаёт **слой**. Docker кэширует слои и пересобирает только то, что изменилось, и всё после него. Поэтому то, что меняется редко (установка зависимостей), ставь выше, а то, что меняется часто (код), ниже. Именно поэтому в примере выше `requirements.txt` копируется отдельно от остального кода.

### .dockerignore

Файл `.dockerignore` рядом с Dockerfile — список того, что не копировать в образ:

```
.git
__pycache__
.env
node_modules
```

## 6. Тома (volumes): сохранение данных

Данные внутри контейнера **пропадают** вместе с ним. Чтобы сохранить (например, базу данных), используй том:

```bash
docker volume create mydata
docker run -d -v mydata:/var/lib/postgresql/data postgres
docker volume ls
```

Можно примонтировать и папку с компьютера (удобно для разработки):

```powershell
docker run -v ${PWD}:/app myimage
```

## 7. Переменные окружения

Передаются через `-e`:

```bash
docker run -d -e POSTGRES_PASSWORD=secret -p 5432:5432 postgres
```

Пароли и ключи не пиши в Dockerfile и не храни в репозитории. Используй `.env`-файл и добавь его в `.gitignore`.

## 8. Docker Compose

Когда контейнеров несколько (приложение + база данных), удобно описать всё в одном файле `compose.yaml`:

```yaml
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: mydb
    volumes:
      - pgdata:/var/lib/postgresql/data
    ports:
      - "5432:5432"

  app:
    build: .
    depends_on:
      - db
    environment:
      DB_HOST: db

volumes:
  pgdata:
```

Команды:

```bash
docker compose up -d       # собрать и запустить всё в фоне
docker compose ps          # состояние сервисов
docker compose logs -f     # логи
docker compose down        # остановить и удалить контейнеры
docker compose down -v     # то же, плюс удалить тома (данные пропадут!)
```

Внутри compose-сети контейнеры обращаются друг к другу **по имени сервиса** (в примере приложение подключается к базе по хосту `db`).

## 9. Типичные ошибки новичков

| Проблема | Причина и решение |
|---|---|
| `Недопустимая метка тома` | Инструкцию Dockerfile (`LABEL`, `FROM`...) ввели в терминал. Её надо писать **в файл** Dockerfile |
| `Cannot connect to the Docker daemon` | Не запущен Docker Desktop |
| `docker build` не находит Dockerfile | Файл назван `Dockerfile.txt` или команда запущена не из той папки |
| Порт уже занят | Смени левый порт: `-p 8081:80` |
| Данные пропали после удаления контейнера | Не использовал том (volume) |
| Предупреждение `JSONArgsRecommended` | `CMD` записан в shell-форме, перепиши в JSON-форме |
| Образ пересобирается слишком долго | Нарушен порядок слоёв, зависимости ставь до копирования кода |
| `code` не найдена в PowerShell | VS Code не в PATH, перезапусти терминал или переустанови с галочкой Add to PATH |

## 10. Шпаргалка: рабочий цикл

1. Написал `Dockerfile`.
2. `docker build -t имя .` — собрал образ.
3. `docker run --rm -p 8080:80 имя` — запустил и проверил.
4. `docker ps`, `docker logs` — посмотрел, что происходит.
5. Исправил, пересобрал.
6. Нужно несколько сервисов, переходи на `compose.yaml`.
